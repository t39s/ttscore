# ttScore Team — журнал изменений

Документ содержит историю реализованных версий `ttscore_team`, начиная с `v0.1`.

## v0.8.7 — 2026-08-29

Статус: **IMPLEMENTED LOCALLY, NOT PUBLISHED, NOT YET ACCEPTED**

Версия построена на `v0.8.6`. `schemaVersion: 4` и структура публикации сохранены. Основное изменение — пакетный рабочий цикл между соседними личными встречами без изменений `ttScore 0.3.5`.

### Изменено

- Добавлен локальный буфер `ttscore_team:pendingFinishedMatch:v1` для последней завершённой личной встречи. Он хранит только `matchId`, `matchDate`, пару, итог по партиям, ID командной/личной встречи и время обнаружения.
- Финальный результат ttScore сохраняется автоматически и переживает перезагрузку страницы судьи.
- Пока ttScore остаётся на том же `matchId`, Undo отслеживается автоматически: если встреча снова становится незавершённой, сохранённый результат удаляется; повторный финал записывает новый итог.
- После появления нового `matchId` предыдущий результат сохраняется, а новая ttScore-встреча принимается только если соответствует следующей `planned`-паре.
- Live следующей встречи может быть включён в тот же JSON, который завершает предыдущую встречу: предыдущая становится `finished`, следующая — `current`, а `liveReportUrl`/`liveScoreboardUrl` относятся уже к новой current-встрече.
- Если live следующей встречи ещё нет, JSON можно подготовить без live; результат предыдущей встречи не блокируется ожиданием трансляции.
- Добавлено reconciliation: если загруженный опубликованный JSON уже содержит сохранённую встречу как `finished` с тем же результатом, локальный буфер автоматически очищается.
- После перехода на новый `matchId` судья может отменить или вручную скорректировать локально сохранённый предыдущий результат до публикации; события live/storage новой встречи не перезаписывают ручную корректировку.

### Проверено

- Автоматические тесты: **165 из 165 пройдены**.
- Проверены: сохранение финала, Undo, повторный финал, новый `matchId`, проверка следующей пары, пакетный переход с live и без live, reconciliation с опубликованным JSON.
- `ttScore 0.3.5` не изменяется.

## v0.8.6 — 2026-08-29

Статус: **IMPLEMENTED LOCALLY, NOT PUBLISHED, NOT YET ACCEPTED**

Версия построена на принятой `v0.8.5`. `schemaVersion: 4`, структура публикации и спортивная логика сохранены. Изменение делает Live-отчёт и Live-табло текущей личной встречи доступными из опубликованного командного JSON на любом устройстве.

### Изменено

- На верхний уровень JSON командной встречи добавлены `liveReportUrl` и `liveScoreboardUrl`. Они относятся только к текущей (`current`) личной встрече и всегда задаются парой либо равны `null`.
- Creator создаёт оба поля со значением `null`; `liveUrl` внутри объектов личных встреч по-прежнему не создаётся.
- В `mode=edit` корректная локальная `ttScore:0.3.5:livePublication` автоматически подставляет обе live-ссылки в любой следующий подготовленный JSON — отдельного действия копирования/переноса live нет.
- Если локальная live-публикация недоступна, уже опубликованная пара live-ссылок сохраняется при обычных правках текущей встречи.
- При переходе `current → finished` обе верхнеуровневые live-ссылки очищаются до назначения следующей `current`, поэтому live предыдущей личной встречи не наследуется новой.
- Публичный режим показывает у текущей личной встречи кнопки `Live-табло` и `Live-отчёт`, используя опубликованные `liveScoreboardUrl` и `liveReportUrl`. Локальный ttScore на устройстве зрителя не требуется.
- В `mode=edit` операционные кнопки используют локальную live-публикацию, если она доступна; иначе — уже сохранённые в JSON ссылки.

### Совместимость

- `schemaVersion: 4` не повышен. JSON `v0.8.5`, где верхнеуровневых live-полей ещё нет, продолжает читаться; при следующем сохранении поля добавляются.
- Legacy `liveUrl` внутри личных встреч по-прежнему разрешён только на входе и удаляется при новом сохранении.
- `reportUrl` завершённой личной встречи остаётся отдельной необязательной постоянной ссылкой.
- Firebase, GitHub API, токены и серверная часть в `ttscore_team` не добавлены; публикация `<id>.json` остаётся ручной.

### Проверено

- Автоматические тесты: **156 из 156 пройдены**.
- Проверены создание пустой пары live-полей, чтение старого JSON без них, парность полей, автоматическое сохранение локальных live URL, сохранение уже опубликованных live URL при обычных правках, очистка при переходе и публичный рендер обеих кнопок.
- Выпускная матрица: **9 из 9** сочетаний 2×2/3×3/4×4 × личные встречи из 3/5/7 партий.
- Синтаксис JavaScript-модулей проверен `node --check`.

Статус: **реализована локально, не опубликована, ещё не принята**.

Версия построена непосредственно на точных байтах `v0.7.0`. `ttScore 0.3.5` не изменялся.

### Добавлено

- В `mode=edit` добавлен блок `Данные из ttScore` для локального обмена с `ttScore 0.3.5` в том же браузере и под тем же origin.
- Интеграция читает существующие `localStorage`-ключи `ttScore:0.3.5:currentMeeting` и `ttScore:0.3.5:livePublication`.

- Добавлено строгое сопоставление текущей пары по именам спортсменов с поддержкой прямого и обратного расположения A/B.

- Публичный режим для `finished` без `reportUrl` показывает `Отчёт не добавлен` вместо пустой ссылки.
