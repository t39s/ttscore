# ttScore Team — журнал изменений

Документ содержит историю реализованных версий `ttscore_team`, начиная с `v0.1`.

## v0.6.0 — 2026-08-27

Статус: **реализована локально, не опубликована, ещё не принята**.

Версия построена непосредственно на точных байтах принятой `v0.5.0`. Основная функция — ручное изменение порядка оставшихся личных встреч во время уже идущей командной встречи.

### Добавлено

- В редакторе запланированные личные встречи можно последовательно перемещать кнопками ↑ и ↓.
- Перестановка меняет только `order`; стабильные ID личных встреч и пары спортсменов сохраняются.
- Завершённые и текущая личные встречи остаются на своих позициях.
- После завершения текущей встречи статус `current` получает первая встреча нового запланированного порядка.
- Добавлено изменение даты, места, названий команд, имён спортсменов и live-ссылки текущей встречи.
- Изменения можно предварительно просмотреть и скачать без завершения текущей личной встречи.
- Добавлен отдельный локальный режим `?mode=edit` для загрузки сохранённого `<id>.json`.
- Опубликованный режим остаётся доступен по `?match=<id>&mode=edit`.

### Источники и защита данных

- Локальный и опубликованный источники строго разделены и не переключаются внутри одной сессии.
- Для опубликованного источника сохранена повторная проверка свежести перед подготовкой и скачиванием.
- Для локального источника явно не выполняются загрузка и сравнение опубликованной версии.
- Исправлено замечание V5-R01 ревью `v0.5.0`: канонические ID спортсменов `a1…aN` и `b1…bN` проверяются до заполнения формы редактора и формы продолжения создания.
- Редактор требует точное имя `<id>.json`, `schemaVersion: 4`, незавершённую встречу и ровно одну текущую личную встречу.

### Сохранено без изменения

- `schemaVersion: 4` и форматы команд 2×2, 3×3 и 4×4.
- Форматы личных встреч `Из 3 партий`, `Из 5 партий` и `Из 7 партий`.
- ID командной встречи, размер команд, формат личных встреч, ID спортсменов, ID и пары личных встреч в редакторе неизменяемы.
- Ручная публикация через GitHub без API, токенов, авторизации и внешних зависимостей.

### Проверено

- Автоматические тесты: **96 из 96 пройдены**.
- Дополнительная матрица: **9 из 9** сочетаний форматов команд и личных встреч пройдены.
- Проверены перестановка только `planned`, стабильность ID и пар, фиксированный порядок `finished/current`, выбор новой следующей встречи, два источника, защита свежести и V5-R01.
- Проверены синтаксис JavaScript, JSON примера, структура HTML и DOM-контракт.

### Границы версии

- Отмена последнего завершения личной встречи отложена до отдельной продуктовой версии.
- Браузерный smoke-тест не выполнен из-за отсутствия браузера в среде сборки.
- Публикация не выполнялась; `ttScore_0.3.5.html` не изменялся.
- Обновлённый changelog входит только в основной ZIP.

## v0.5.0 — 2026-08-27

Статус: **принята пользователем, не опубликована**.

Версия построена непосредственно на точных байтах принятой `v0.4.1`. Схема JSON и внешние зависимости не изменены.

### Добавлено

- В режиме создания добавлена локальная загрузка ранее сохранённого JSON.
- Загруженный файл проходит строгую проверку `schemaVersion: 4`, имени `<id>.json`, подготовительного состояния, канонического названия, ID и порядка личных встреч.
- Форма восстанавливает команды, составы, дату, место, форматы, первую live-ссылку и пользовательский порядок пар.
- После редактирования файл повторно скачивается под тем же исходным именем; ID загруженной встречи заблокирован от изменения.
- Размер импортируемого файла ограничен 1 МиБ.

### Изменено

- Ручные изменения полей больше не сбрасывают уже переставленный порядок пар; смена формата команд пересоздаёт порядок полностью.
- Исправлено замечание R-01 ревью `v0.4.1`: диагностическое сообщение «после пятой победы» заменено универсальным «после завершения командной встречи» для форматов 2×2, 3×3 и 4×4.

### Совместимость и границы

- Новая миграционная логика не добавлена; импорт принимает только `schemaVersion: 4`.
- Унаследованное чтение `schemaVersion: 3` публичным режимом и редактором не изменялось, но в режим продолжения подготовки эта схема не загружается.
- Начатые и завершённые встречи не импортируются в режим создания; для них остаётся `mode=edit`.
- JSON читается локально и не отправляется в GitHub; публикация остаётся ручной.
- GitHub API, авторизация, токены и внешние зависимости не добавлены.

### Проверено

- Автоматические тесты: **84 из 84 пройдены**.
- Проверены успешный импорт, сохранение имени и порядка, запрет `schemaVersion: 3`, ошибочный JSON, неверное имя, некорректный `title` и уже начатая встреча.
- Универсальное сообщение после завершения проверено для 2×2, 3×3 и 4×4.
- Проверены синтаксис JavaScript, JSON примера, структура HTML и DOM-контракт.

### Границы версии

- Браузерный E2E не выполнен; перед принятием требуется ручной smoke-тест импорта и повторного скачивания.
- Публикация не выполнялась.
- `ttScore_0.3.5.html` не изменялся.
- Обновлённый changelog входит только в основной ZIP.

## v0.4.1 — 2026-08-27

Статус: **принята пользователем, не опубликована**.

Добавлена настройка единого формата личных встреч при создании командного расписания. Версия построена на принятой `v0.4.0` без новых внешних зависимостей.

### Добавлено

- В режиме создания доступны только варианты `Из 3 партий`, `Из 5 партий` и `Из 7 партий`; значение по умолчанию — `Из 5 партий`.
- Новый JSON получает `schemaVersion: 4` и одно исходное поле `individualMatchBestOf: 3 | 5 | 7`.
- Публичная страница показывает выбранный формат как `Из N партий`.
- Редактор результата динамически формирует значения счёта для выбранного формата.

### Совместимость

- `schemaVersion: 3` продолжает читаться и трактуется как `Из 5 партий`.
- `schemaVersion: 4` строго требует `individualMatchBestOf`; строки, boolean и значения вне `3 | 5 | 7` отклоняются.
- Расписание, перестановка пар, командный автомат, ссылки и ручная публикация JSON не изменены.

### Проверено

- Автоматические тесты: **79 из 79 пройдены**.
- Проверены создание, просмотр и обновление для всех трёх форматов личных встреч.
- Проверены допустимые и недопустимые результаты, обратная совместимость `schemaVersion: 3` и строгий контракт `schemaVersion: 4`.
- Повторно проверены все регрессии принятой `v0.4.0`.

### Границы версии

- В одной командной встрече используется единый формат всех личных встреч.
- Браузерный E2E не выполнен из-за ограничения среды; перед принятием требуется ручная проверка.
- Публикация не выполнялась.

## v0.3.1 — 2026-08-27

Статус: **принята пользователем, не опубликована**.

Исправленная patch-версия создана на основе точной `v0.3.0` по результатам её формального ревью. Продуктовые возможности и `schemaVersion: 3` не расширялись.

### Исправлено

- **R-01:** `winsToFinish`, `order`, `gamesA` и `gamesB` принимаются только как целые JSON-числа; строки, boolean и `null` больше не преобразуются через `Number(...)`.
- **R-02:** `updatedAt` проверяется как реальная календарная дата и допустимое время; исключены 31 февраля, часы `24`, минуты или секунды `60`, а также смещения за пределами `±14:00`.
- **R-03:** начальная дата в режиме создания определяется по локальному календарному дню пользователя, а не по UTC.
- **R-04:** при подготовке предварительного просмотра и перед скачиванием выполняется проверка существования опубликованного `<id>.json`; совпадение вызывает предупреждение о замене. Ошибка или четырёхсекундный тайм-аут не блокируют скачивание, поэтому финальный GitHub diff остаётся обязательным контролем.

### Сохранено без изменения

- Форматы 2×2, 3×3 и 4×4, циклическое расписание и личные встречи до трёх побед в партиях.
- Режимы `create`, `view` и `edit` и открытая JSON-модель `schemaVersion: 3`.
- Ручная загрузка JSON через GitHub без API, токена и авторизации в приложении.
- Отделение общего исходного кода от файлов конкретных встреч.

### Проверено

- Автоматические тесты: **67 из 67 пройдены**.
- Добавлены регрессии для строгих числовых типов, невозможных даты, времени и часового пояса, локального календарного дня и классификации результата проверки ID.
- Проверены синтаксис JavaScript, JSON примера, структура HTML, контрольные суммы и HTTP-выдача файлов.

### Границы версии

- Проверка ID носит предупредительный характер и не резервирует имя файла; GitHub diff обязателен.
- Браузерный E2E не выполнен из-за ограничения среды; перед принятием требуется ручная проверка.
- Публикация не выполнялась.
- Отдельный ZIP changelog не создаётся; обновлённый журнал входит только в основной пакет.

## v0.3.0 — 2026-08-27

Статус: **прошла формальное ревью, не принята; замечания исправлены в `v0.3.1`**.

- Результаты `3:0`, `3:1`, `3:2` и зеркальные.

- Защита редактора от устаревшего источника.

## v0.2.1 — 2026-08-27

Статус: **реализована локально, не опубликована, ещё не принята**.

### Добавлено

- В `ttscore_team_0.2.1.html` добавлен отдельный режим `?match=<id>&mode=edit` для подготовки обновлённого JSON.
- Редактор автоматически загружает опубликованный JSON; начальный выбор локального файла не требуется.
- Форма принимает итог завершённой личной встречи, обязательный `reportUrl` и необязательный `liveUrl` следующей встречи.
- Одна проверяемая операция завершает текущую встречу, пересчитывает командный счёт и при необходимости запускает следующую.
- После пятой победы следующая встреча не назначается, а оставшиеся позиции отображаются как `Не требовалась`.
- Перед сохранением показываются итоговый командный счёт, следующая встреча или факт завершения, а также полный JSON.
- Файл сохраняется под точным именем `<id>.json` для последующей ручной загрузки в GitHub.

### Изменено

- `meeting-source.mjs` переименован в `matches-source.mjs` во всём коде, тестах и документации.
