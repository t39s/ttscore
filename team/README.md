# ttScore Team v0.2.0

## Статус

- Назначение: статическое публичное оглавление одной командной встречи.
- Версия: `v0.2.0`.
- Статус: `IMPLEMENTED LOCALLY, NOT PUBLISHED, NOT YET ACCEPTED`.
- Данные примера: вымышленные.

`ttscore_team` не ведёт счёт личной встречи и не изменяет `ttScore 0.3.5`.
Каждая личная встреча проводится отдельно в готовом `ttScore`, а командная страница хранит только расписание, командный результат и ссылки.

## Структура

```text
team/
  ttscore_team_0.2.0.html       — единая страница всех командных встреч
  assets/0.2.0/                 — общий исходный код версии
    app.mjs
    meeting-source.mjs
    model.mjs
    styles.css
  team-matches/                 — данные конкретных командных встреч
    sever-yug-2026-09-05.json   — вымышленный пример
tests/
  meeting-source.test.mjs
  model.test.mjs
  static-structure.test.mjs
ttscore_team_changelog.md
SHA256SUMS.md
```

Исходный код не содержит названий команд, спортсменов, даты, порядка пар, результатов или ссылок конкретной встречи.

## Адрес командной встречи

После публикации пример открывается по адресу:

```text
https://t39s.github.io/ttscore/team/ttscore_team_0.2.0.html?match=sever-yug-2026-09-05
```

Параметр `match` обязателен. Разрешены только строчные латинские буквы, цифры и дефисы; это исключает подстановку произвольного пути.

## Создание новой командной встречи

1. Скопировать файл из `team/team-matches/`.
2. Назвать копию `<id>.json`.
3. Записать тот же `<id>` в корневом поле `id`.
4. Заполнить команды, спортсменов и девять элементов `individualMatches`.
5. Открыть `ttscore_team_0.2.0.html?match=<id>`.

HTML, JavaScript и CSS для новой встречи копировать или изменять не нужно.

## Модель JSON

`v0.2.0` принимает только `schemaVersion: 2`.

Основные поля:

- `id` — постоянный идентификатор командной встречи;
- `teams` — две команды `A` и `B`, по три спортсмена;
- `individualMatches` — девять уникальных межкомандных пар;
- `winsToFinish` — фиксированное значение `5`;
- `updatedAt` — время последнего ручного изменения данных.

До пятой победы элементы `individualMatches` должны идти в последовательности:

```text
finished* → current? → planned*
```

После пятой победы в JSON остаются только `planned`-позиции, а страница отображает их как `Не требовалась`.

## Обновление встречи

Редактируется только соответствующий файл в `team/team-matches/`.

Для начала личной встречи:

```json
{
  "status": "current",
  "result": null,
  "liveUrl": "https://ссылка-из-ttscore",
  "reportUrl": null
}
```

После завершения личной встречи:

```json
{
  "status": "finished",
  "result": { "gamesA": 3, "gamesB": 1 },
  "liveUrl": "https://ссылка-из-ttscore",
  "reportUrl": "https://ссылка-на-отчёт"
}
```

Для `finished` обязательны результат и `reportUrl`. Командный счёт вручную не вводится.
При каждом изменении нужно обновлять `updatedAt` в формате ISO 8601.

## Отчёты

`reportUrl` — универсальная ссылка на опубликованный отчёт `ttScore`. Она может вести на:

- автономный HTML-отчёт;
- защищённый отчёт `.ttscore`;
- открытый JSON.

Формат, размещение и публикация отчёта находятся вне ответственности `ttscore_team`.
Если защищённая ссылка размещена на публичной командной странице, её ключ доступен всем посетителям страницы.

## Обновление страницы

Страница перечитывает JSON каждые 30 секунд, пока вкладка видима. Кнопка `Обновить` запускает загрузку немедленно.
При ошибке повторной загрузки последние успешные данные остаются на экране и помечаются как устаревшие.

## Локальный запуск

Из каталога `ttscore_team_v0.2.0`:

```bash
python3 -m http.server 8000
```

Открыть:

```text
http://localhost:8000/team/ttscore_team_0.2.0.html?match=sever-yug-2026-09-05
```

Режим `file://` не поддерживается, поскольку браузер блокирует загрузку соседнего JSON.

## Тесты

```bash
node --test tests/*.test.mjs
```

Тесты проверяют спортивную модель, строгий JSON-контракт, универсальный `reportUrl`, параметр `match`, защиту от обхода пути и отсутствие данных примера в общем коде.

В подготовленном пакете пройдены **23 из 23** автоматических тестов. Браузерный E2E локальной страницы не выполнен из-за отсутствия разрешения среды на доступ облачного браузера к локальному HTTP-серверу.

## Публичность данных

Командные JSON-файлы, результаты, live-ссылки и `reportUrl` публикуются открыто.
При размещении в публичном GitHub-репозитории данные перечислимы, могут индексироваться и сохраняются в истории commit.
Защита от изменения обеспечивается правами записи в репозиторий.

## Публикация

Публикация не выполнялась. Для GitHub Pages нужно загрузить каталог `team/` в репозиторий `ttscore` и использовать URL с параметром `match`.
Firebase, Firebase Hosting и изменение `ttScore_0.3.5.html` этой версии не требуются.
