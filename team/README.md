## Статус

- Версия: `v0.6.0`.
- Статус: `IMPLEMENTED LOCALLY, NOT PUBLISHED, NOT YET ACCEPTED`.
- Основа: точные байты принятой `v0.5.0`.
- Назначение: создание, ручное обновление и публичное оглавление одной командной встречи.

`ttscore_team` не ведёт счёт личной встречи и не изменяет `ttScore 0.3.5`. Каждая личная встреча проводится отдельно в готовом `ttScore`, а в JSON командной встречи сохраняются её результат, live-ссылка и универсальная ссылка на отчёт.

## Форматы

Каждый спортсмен команды A играет с каждым спортсменом команды B.

| Формат | Личных встреч | Побед для досрочного завершения | Возможная ничья |
|---|---:|---:|---:|
| 2×2 | 4 | 3 | 2:2 |
| 3×3 | 9 | 5 | Нет |
| 4×4 | 16 | 9 | 8:8 |

Для всех личных встреч командной встречи используется один выбранный формат: `Из 3 партий`, `Из 5 партий` или `Из 7 партий`.

## Создание командной встречи

```text
ttscore_team_0.6.0.html?mode=create
```

Форма принимает ID, дату, место, формат команд, формат личных встреч, названия команд, имена спортсменов и необязательную live-ссылку первой встречи. Расписание создаётся автоматически; до скачивания пары можно переставлять кнопками ↑ и ↓.

После проверки показываются расписание, путь `team/team-matches/<id>.json`, публичный URL и полный JSON. Файл скачивается под точным именем `<id>.json`.

Режим создания также загружает ранее скачанный подготовительный JSON `schemaVersion: 4`. Он восстанавливает форму и порядок пар. ID загруженной встречи остаётся заблокированным. Начатая встреча должна редактироваться в `mode=edit`.

## Публичный режим

```text
ttscore_team_0.6.0.html?match=<id>
```

Страница показывает сведения о встрече, составы, командный счёт, расписание, live-ссылки и ссылки на отчёты. `reportUrl` может вести, например, на автономный HTML-отчёт, открытый JSON или защищённый отчёт `ttScore`.

## Редактирование идущей встречи

### Опубликованный источник

```text
ttscore_team_0.6.0.html?match=<id>&mode=edit
```

Редактор загружает опубликованный `team/team-matches/<id>.json`. Перед подготовкой и перед скачиванием он повторно проверяет, что опубликованный источник не изменился.

### Локальный источник

```text
ttscore_team_0.6.0.html?mode=edit
```

Пользователь выбирает локально сохранённый `<id>.json`. Файл читается только браузером и никуда не отправляется. Опубликованный JSON в этом режиме не загружается и не сравнивается. Смешивать локальный и опубликованный источники в одной сессии нельзя.

Для обоих источников редактор поддерживает:

- изменение даты, места, названий команд и имён спортсменов;
- изменение live-ссылки текущей личной встречи;
- перестановку только запланированных встреч кнопками ↑ и ↓;
- предварительный просмотр и скачивание JSON без завершения текущей встречи;
- завершение текущей встречи, добавление обязательной ссылки на отчёт и запуск первой встречи из нового запланированного порядка.

У завершённых и текущей встреч порядок фиксирован. При перестановке меняется только `order` запланированных встреч: стабильные ID личных встреч и их пары сохраняются.

В режиме редактирования нельзя менять:

- ID командной встречи;
- формат 2×2, 3×3 или 4×4;
- формат личных встреч;
- ID спортсменов;
- ID и состав пар личных встреч;
- результат и отчёт уже завершённой встречи.

Перед заполнением формы проверяется канонический порядок ID спортсменов `a1…aN` и `b1…bN`. Это исключает запись исправленных имён не тем спортсменам.

Отмена последнего завершения личной встречи в `v0.6.0` не реализована.

## Ручная публикация JSON

1. Скачать подготовленный `<id>.json`.
2. Открыть в GitHub каталог `team/team-matches/`.
3. Заменить файл с тем же точным именем.
4. Проверить GitHub diff.
5. Создать commit.

Приложение не использует GitHub API, токены, авторизацию, Firebase или серверную часть.

## Модель JSON

Версия сохраняет `schemaVersion: 4`. Поле `individualMatchBestOf` принимает только `3`, `5` или `7`.

Редактор принимает только `schemaVersion: 4`, точное имя `<id>.json`, незавершённую командную встречу и ровно одну текущую личную встречу. Автоматической миграции прежних схем нет.

Модель проверяет размеры команд, полное покрытие пар, порог побед, последовательность статусов, результаты личных встреч, обязательность отчёта, дату, `updatedAt`, допустимые URL, целые JSON-числа и отсутствие неизвестных полей.

## Локальный запуск

Из каталога `ttscore_team_v0.6.0`:

```bash
python3 -m http.server 8000
```

Основные адреса:

```text
http://localhost:8000/team/ttscore_team_0.6.0.html?mode=create
http://localhost:8000/team/ttscore_team_0.6.0.html?match=sever-yug-2026-09-05
http://localhost:8000/team/ttscore_team_0.6.0.html?match=sever-yug-2026-09-05&mode=edit
http://localhost:8000/team/ttscore_team_0.6.0.html?mode=edit
```

Режим `file://` не поддерживается.

## Тесты

```bash
node --test tests/*.test.mjs
```

В пакете пройдены **96 из 96** автоматических тестов. Дополнительная выпускная матрица проверила **9 из 9** сочетаний форматов команд 2×2/3×3/4×4 и личных встреч из 3/5/7 партий.

Проверены два взаимоисключающих источника, редактируемые и неизменяемые поля, стабильность ID и пар, перестановка только `planned`, запуск первой встречи нового порядка, защита свежести опубликованного JSON, локальная загрузка, исправление V5-R01, строгая модель и DOM-контракт.

Браузерный smoke-тест не выполнен: браузер в среде сборки отсутствует. Перед принятием рекомендуется вручную проверить обе ветви редактора, перестановку пар, предварительный просмотр и скачивание.

## Границы версии

Не реализованы отмена завершения, изменение спортивного формата и состава пар начатой встречи, drag-and-drop, GitHub API, автоматическая публикация и серверная часть. Публикация не выполнялась; `ttScore_0.3.5.html` не изменялся.
