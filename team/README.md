# ttScore Team v0.2.2

## Статус

- Назначение: статическое публичное оглавление одной командной встречи.
- Версия: `v0.2.2`.
- Статус: `IMPLEMENTED LOCALLY, NOT PUBLISHED, NOT YET ACCEPTED`.
- Основа: точные принятые байты `v0.2.1`.
- Данные примера: вымышленные.

`ttscore_team` не ведёт счёт личной встречи и не изменяет `ttScore 0.3.5`. Каждая личная встреча проводится отдельно в готовом `ttScore`, а командная страница хранит расписание, командный результат и ссылки.

## Режим подготовки обновления

```text
https://t39s.github.io/ttscore/team/ttscore_team_0.2.2.html?match=sever-yug-2026-09-05&mode=edit
```

Редактор автоматически загружает опубликованный JSON выбранной встречи.

1. Указать итог по партиям: `3:0`, `3:1`, `3:2` или зеркальный.
2. Вставить обязательную ссылку на отчёт завершённой встречи.
3. При наличии следующей встречи при желании вставить её live-ссылку.
4. Нажать **Подготовить обновление**.
5. Проверить новый командный счёт, следующую встречу или завершение командной встречи.
6. Нажать **Сохранить `<id>.json`**.

Страница:

- переводит текущую встречу из `current` в `finished`;
- записывает результат и `reportUrl`;
- сохраняет прежний `liveUrl` завершённой встречи;
- пересчитывает командный счёт;
- при отсутствии пятой победы переводит первую `planned`-встречу в `current`;
- после пятой победы не запускает следующую встречу;
- обновляет `updatedAt`;
- повторно проверяет весь JSON.

## Защита от устаревшего источника

Перед подготовкой и повторно перед скачиванием редактор загружает опубликованный JSON с отключённым кэшем и сравнивает его устойчивую ревизию с исходным файлом.

Если JSON изменился, операция блокируется. Нужно нажать **Обновить** и ввести данные заново. Ручное обновление всегда очищает форму; при смене текущей встречи страница показывает прежний и новый ID.

Проверка не резервирует файл в GitHub: между скачиванием и ручным commit теоретически возможно другое изменение. Поэтому просмотр GitHub diff перед commit остаётся обязательным последним контролем.

## Ручная загрузка в GitHub

Редактор не хранит токен GitHub, не выполняет вход и не отправляет файл в репозиторий.

1. Открыть в GitHub каталог `team/team-matches/`.
2. Загрузить сохранённый JSON, заменив одноимённый файл встречи.
3. Убедиться, что имя в точности совпадает с `<id>.json`.
4. Если браузер добавил `(1)`, переименовать файл обратно.
5. Проверить diff: должна завершиться только ожидаемая текущая встреча и при необходимости начаться следующая.
6. Создать commit.

Защищённая ветка или ruleset могут потребовать отдельную ветку и pull request.

## Строгая модель JSON

Версия сохраняет `schemaVersion: 2`. Командный счёт вычисляется из `individualMatches` и не хранится отдельно.

До пятой победы состояния идут в последовательности:

```text
finished* → current? → planned*
```

После пятой победы оставшиеся исходные позиции сохраняются как `planned`, а страница отображает их как `Не требовалась`.

Все строки должны быть каноническими: начальные и конечные пробелы запрещены. `updatedAt` требует ISO 8601 с часовым поясом.

`reportUrl` может вести на автономный HTML-отчёт, защищённый отчёт `.ttscore` или открытый JSON. Разрешены относительные ссылки и HTTP(S). Запрещены активные схемы, protocol-relative URL, обратные косые черты, сегменты `..`, включая percent-encoded вариант, и некорректное percent-encoding.

## Новая командная встреча

Для новой встречи достаточно добавить `team/team-matches/<id>.json`, записав тот же `<id>` в корневом поле `id`. HTML, JavaScript и CSS изменять не нужно.

## Локальный запуск

Из каталога `ttscore_team_v0.2.2`:

```bash
python3 -m http.server 8000
```

Публичный режим:

```text
http://localhost:8000/team/ttscore_team_0.2.2.html?match=sever-yug-2026-09-05
```

Редактор:

```text
http://localhost:8000/team/ttscore_team_0.2.2.html?match=sever-yug-2026-09-05&mode=edit
```

Режим `file://` не поддерживается.

## Публичность и границы

Командные JSON-файлы, составы, результаты, live-ссылки и `reportUrl` публикуются открыто и сохраняются в истории Git. Защита от изменения обеспечивается правами записи в репозиторий.

Публикация не выполнялась. Firebase, Firebase Hosting, GitHub API и изменение `ttScore_0.3.5.html` не требуются.
