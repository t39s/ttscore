## Форматы

Каждый спортсмен команды A играет с каждым спортсменом команды B.

| Формат | Личных встреч | Побед для досрочного завершения | Возможная ничья |
|---|---:|---:|---:|
| 2×2 | 4 | 3 | 2:2 |
| 3×3 | 9 | 5 | Нет |
| 4×4 | 16 | 9 | 8:8 |

Формат личной встречи выбирается при создании:

- `Из 3 партий`;
- `Из 5 партий`;
- `Из 7 партий`.

Допустимые результаты определяются выбранным форматом.

## Создание командной встречи

```text
https://t39s.github.io/ttscore/team/ttscore_team_0.5.0.html?mode=create
```

Форма принимает:

- постоянный идентификатор;
- дату;
- необязательное место;
- формат 2×2, 3×3 или 4×4;
- формат личных встреч: `Из 3 партий`, `Из 5 партий` или `Из 7 партий`;
- названия команд;
- имена спортсменов;
- необязательную live-ссылку первой встречи.

Название формируется как `Команда A — Команда B`. Спортсмены получают ID `a1…aN` и `b1…bN`.

Расписание создаётся автоматически в циклическом порядке. До скачивания любую пару можно последовательно перемещать кнопками ↑ и ↓. После каждого перемещения JSON пересобирается: пары получают номера и ID `m01…mNN` по новому порядку. Первая личная встреча получает статус `current` и первую live-ссылку, остальные — `planned`.

После полной проверки показываются расписание, путь `team/team-matches/<id>.json`, готовый адрес публичной страницы и полный JSON. Скачивается точный файл `<id>.json`.

При подготовке предварительного просмотра и ещё раз перед скачиванием выполняется неблокирующая проверка существования опубликованного `<id>.json`. Совпадение ID вызывает предупреждение о замене файла, но не запрещает скачивание. Если проверка недоступна или не завершилась за четыре секунды, обязательным контролем остаётся GitHub diff.

## Публикация созданного JSON

1. Открыть в GitHub каталог `team/team-matches/`.
2. Загрузить `<id>.json`.
3. Если браузер добавил `(1)`, восстановить точное имя.
4. Проверить diff.
5. Создать commit.

Приложение не использует GitHub API, токены или авторизацию.

## Продолжение подготовки из локального JSON

В режиме создания кнопка «Загрузить JSON» принимает ранее скачанный файл командной встречи. Файл читается локально средствами браузера и никуда не отправляется.

Импорт допускается только при одновременном выполнении условий:

- `schemaVersion` строго равен `4`;
- имя файла точно равно `<id>.json`;
- JSON соответствует строгой модели;
- первая личная встреча имеет исходный статус `current`, остальные — `planned`;
- результатов завершённых личных встреч ещё нет;
- `title`, ID личных встреч и расписание имеют канонический вид, создаваемый приложением.

После загрузки восстанавливаются команды, составы, дата, место, форматы, первая live-ссылка и пользовательский порядок пар. Их можно изменить, пары можно переставить и затем снова скачать JSON под исходным именем. Идентификатор загруженного файла заблокирован от изменения, чтобы имя и `id` не разошлись.

JSON начатой или завершённой встречи нужно обновлять в существующем `mode=edit`. Импорт `schemaVersion: 3` и преобразование схемы не реализованы.

## Публичный режим

```text
ttscore_team_0.5.0.html?match=<id>
```

Страница показывает формат команд, формат личных встреч `Из N партий`, составы, командный счёт, расписание, live-ссылки и отчёты. Для форматов 2×2 и 4×4 поддерживается итоговая ничья.

## Режим обновления

```text
ttscore_team_0.5.0.html?match=<id>&mode=edit
```

Редактор формирует варианты результата согласно `Из 3 партий`, `Из 5 партий` или `Из 7 партий`, завершает текущую личную встречу и запускает следующую, если командная встреча не завершена победой или ничьей. Сохраняются защита от устаревшего опубликованного JSON, очистка формы после ручного обновления и повторная проверка перед скачиванием.

## Модель JSON

Новые JSON создаются с `schemaVersion: 4` и обязательным полем:

```json
"individualMatchBestOf": 5
```

Значения поля: `3`, `5` или `7`. Унаследованные публичный режим и редактор по-прежнему читают `schemaVersion: 3` как `Из 5 партий`, однако режим продолжения подготовки принимает только `schemaVersion: 4` и ничего не преобразует.

Модель проверяет:

- одинаковый размер команд от двух до четырёх спортсменов;
- ровно `N²` личных встреч;
- каждую межкомандную пару ровно один раз;
- правильный `winsToFinish`;
- последовательность `finished* → current? → planned*`;
- завершение после большинства или ничью после всех встреч;
- обязательный результат и `reportUrl` для `finished`;
- соответствие результата формату личной встречи;
- фактические целые JSON-числа без преобразования строк и boolean;
- канонические строки, реальную календарную дату и время ISO 8601 с корректным часовым поясом;
- безопасные ссылки.

JSON `schemaVersion: 2` продолжает использовать страницу `v0.2.2`. Автоматическая миграция в эту версию не входит.

## Локальный запуск

Из каталога `ttscore_team_v0.5.0`:

```bash
python3 -m http.server 8000
```

Создание:

```text
http://localhost:8000/team/ttscore_team_0.5.0.html?mode=create
```

Просмотр примера:

```text
http://localhost:8000/team/ttscore_team_0.5.0.html?match=sever-yug-2026-09-05
```

Режим `file://` не поддерживается.

## Тесты

```bash
node --test tests/*.test.mjs
```

В пакете пройдены **84 из 84** автоматических тестов. Проверены три формата команд и три формата личных встреч, создание и локальный импорт `schemaVersion: 4`, запрет миграции `schemaVersion: 3`, сохранение исходного имени и порядка пар, отклонение уже начатой встречи, допустимые результаты, динамический редактор, путь JSON, публичный URL, режимы `create`, `view`, `edit`, строгая модель и DOM-контракт.

Браузерный E2E не выполнен из-за ограничения среды. Перед принятием требуется ручная проверка создания, импорта, редактирования и повторного скачивания JSON.

## Границы версии

Не реализованы произвольное перетаскивание мышью, импорт `schemaVersion: 3`, редактирование начатой встречи через режим создания, прямое сохранение в GitHub, парные встречи и форматы личной встречи кроме 3, 5 и 7 партий.

Публикация не выполнялась. Firebase и изменение `ttScore_0.3.5.html` не требуются.
