## Форматы

Каждый спортсмен команды A играет с каждым спортсменом команды B.

| Формат | Личных встреч | Побед для досрочного завершения | Возможная ничья |
|---|---:|---:|---:|
| 2×2 | 4 | 3 | 2:2 |
| 3×3 | 9 | 5 | Нет |
| 4×4 | 16 | 9 | 8:8 |

Результат личной встречи: `3:0`, `3:1`, `3:2` или зеркальный.

## Создание командной встречи

```text
https://t39s.github.io/ttscore/team/ttscore_team_0.3.1.html?mode=create
```

Форма принимает:

- постоянный идентификатор;
- дату;
- необязательное место;
- формат 2×2, 3×3 или 4×4;
- названия команд;
- имена спортсменов;
- необязательную live-ссылку первой встречи.

Название формируется как `Команда A — Команда B`. Спортсмены получают ID `a1…aN` и `b1…bN`.

Расписание создаётся автоматически в циклическом порядке. Первая личная встреча получает статус `current`, остальные — `planned`. Ручная перестановка в первой версии не предусмотрена.

После полной проверки показывается JSON и сохраняется точный файл `<id>.json`.

При подготовке предварительного просмотра и ещё раз перед скачиванием выполняется неблокирующая проверка существования опубликованного `<id>.json`. Совпадение ID вызывает предупреждение о замене файла, но не запрещает скачивание. Если проверка недоступна или не завершилась за четыре секунды, обязательным контролем остаётся GitHub diff.

## Публикация созданного JSON

1. Открыть в GitHub каталог `team/team-matches/`.
2. Загрузить `<id>.json`.
3. Если браузер добавил `(1)`, восстановить точное имя.
4. Проверить diff.
5. Создать commit.

Приложение не использует GitHub API, токены или авторизацию.

## Публичный режим

```text
ttscore_team_0.3.1.html?match=<id>
```

Страница показывает формат, составы, командный счёт, расписание, live-ссылки и отчёты. Для форматов 2×2 и 4×4 поддерживается итоговая ничья.

## Режим обновления

```text
ttscore_team_0.3.1.html?match=<id>&mode=edit
```

Редактор завершает текущую личную встречу и запускает следующую, если командная встреча не завершена победой или ничьей. Сохраняются защита от устаревшего опубликованного JSON, очистка формы после ручного обновления и повторная проверка перед скачиванием.

## Модель JSON

`v0.3.1` использует только `schemaVersion: 3`.

Модель проверяет:

- одинаковый размер команд от двух до четырёх спортсменов;
- ровно `N²` личных встреч;
- каждую межкомандную пару ровно один раз;
- правильный `winsToFinish`;
- последовательность `finished* → current? → planned*`;
- завершение после большинства или ничью после всех встреч;
- обязательный результат и `reportUrl` для `finished`;
- фактические целые JSON-числа без преобразования строк и boolean;
- канонические строки, реальную календарную дату и время ISO 8601 с корректным часовым поясом;
- безопасные ссылки.

JSON `schemaVersion: 2` продолжает использовать страницу `v0.2.2`. Автоматическая миграция в эту версию не входит.

## Локальный запуск

Из каталога `ttscore_team_v0.3.1`:

```bash
python3 -m http.server 8000
```

Создание:

```text
http://localhost:8000/team/ttscore_team_0.3.1.html?mode=create
```

Просмотр примера:

```text
http://localhost:8000/team/ttscore_team_0.3.1.html?match=sever-yug-2026-09-05
```

Режим `file://` не поддерживается.

## Тесты

```bash
node --test tests/*.test.mjs
```

В пакете пройдены **67 из 67** автоматических тестов. Проверены генерация трёх форматов, циклический порядок, уникальность пар, победы, ничьи, режимы `create`, `view`, `edit`, защита редактора, строгие типы JSON, календарная корректность `updatedAt`, локальная дата, проверка совпадения ID, DOM-контракт и HTTP-выдача файлов.

Браузерный E2E не выполнен из-за ограничения среды. Перед принятием требуется ручная проверка создания, скачивания и повторного открытия JSON каждого формата.

## Границы первой версии создания

Не реализованы ручная перестановка расписания, редактирование созданного JSON в форме, импорт локального JSON, прямое сохранение в GitHub, парные встречи и другой формат личной встречи.

Публикация не выполнялась. Firebase и изменение `ttScore_0.3.5.html` не требуются.
