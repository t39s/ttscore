# ttScore Team v0.8.3

## Статус

- Версия: `v0.8.3`.
- Статус: `IMPLEMENTED LOCALLY, NOT PUBLISHED, NOT YET ACCEPTED`.
- Основа: `v0.8.2`; структура публикации и интеграционный контракт сохранены, `mode=edit` доработан по результатам UI/UX-ревью.
- Назначение: создание, ручное обновление и публичное оглавление одной командной встречи.

`ttscore_team` не ведёт счёт личной встречи и не изменяет `ttScore 0.3.5`. Каждая личная встреча проводится отдельно в готовом `ttScore`. В `mode=edit` версия `v0.8.3` может локально обнаружить текущую встречу `ttScore 0.3.5` в том же браузере и предложить перенести live-ссылку и финальный результат в существующие поля редактора.

## Форматы

Каждый спортсмен команды A играет с каждым спортсменом команды B.

| Формат | Личных встреч | Побед для досрочного завершения | Возможная ничья |
|---|---:|---:|---:|
| 2×2 | 4 | 3 | 2:2 |
| 3×3 | 9 | 5 | Нет |
| 4×4 | 16 | 9 | 8:8 |

Для всех личных встреч командной встречи используется один выбранный формат: `Из 3 партий`, `Из 5 партий` или `Из 7 партий`.

## Создание командной встречи

```text
ttscore_team_0.8.3.html?mode=create
```

Форма принимает ID, дату, место, формат команд, формат личных встреч, названия команд, имена спортсменов и необязательную live-ссылку первой встречи. Расписание создаётся автоматически; до сохранения пары можно переставлять кнопками ↑ и ↓.

После проверки показываются расписание, путь `team/matches/<id>/<id>.json`, публичный URL и полный JSON. Файл сохраняется под точным именем `<id>.json`. Для публикации создаётся одноимённый каталог `team/matches/<id>/`.

Режим создания также загружает ранее скачанный подготовительный JSON `schemaVersion: 4`. Он восстанавливает форму и порядок пар. ID загруженной встречи остаётся заблокированным. Начатая встреча должна редактироваться в `mode=edit`.

## Публичный режим

```text
ttscore_team_0.8.3.html?match=<id>
```

Страница показывает сведения о встрече, составы, командный счёт, расписание, live-ссылки и ссылки на отчёты. `reportUrl` может вести, например, на автономный HTML-отчёт, открытый JSON или защищённый отчёт `ttScore`. Относительный `reportUrl` разрешается от каталога `team/matches/<id>/`, поэтому отчёты личных встреч можно публиковать рядом с `<id>.json`.

Во время командной встречи статус показывает номер текущей личной встречи и порог побед:

> Идёт личная встреча № N. Для победы команде нужно выиграть M личных встреч.

`N` берётся из `order` текущей встречи, `M` — из `winsToFinish`. После завершения командной встречи вместо этой строки показывается итог.

## Редактирование командной встречи

### Опубликованный источник

```text
ttscore_team_0.8.3.html?match=<id>&mode=edit
```

Редактор загружает опубликованный `team/matches/<id>/<id>.json`. Непосредственно перед подготовкой итогового JSON он повторно проверяет, что опубликованный источник не изменился.

### Локальный источник

```text
ttscore_team_0.8.3.html?mode=edit
```

Пользователь выбирает локально сохранённый `<id>.json`. Файл читается только браузером и никуда не отправляется. Опубликованный JSON в этом режиме не загружается и не сравнивается. Смешивать локальный и опубликованный источники в одной сессии нельзя.

В `v0.8.3` редактор расположен сразу после командного статуса, до полного публичного списка личных встреч. Это сокращает путь до основного действия в `mode=edit`, особенно для формата 4×4.

Для обоих источников редактор поддерживает:

- сворачиваемый раздел ссылок всех личных встреч;
- ввод, замену и допустимую очистку `Live-ссылки` и `Отчёта` независимо от счёта и переходов;
- изменение даты, места, названий команд и имён спортсменов;
- перестановку только запланированных встреч кнопками ↑ и ↓;
- единое действие `Подготовить JSON с изменениями`, которое включает все текущие правки ссылок, сведений и planned-порядка;
- завершение текущей встречи, которое также включает весь текущий черновик редактора перед применением результата;
- отдельное `Перезагрузить источник` для опубликованного JSON непосредственно в рабочей области editor.

Для завершённой командной встречи `mode=edit` автоматически раскрывает раздел ссылок; формы сведений, счёта, перехода и перестановки скрыты. `liveUrl` и `reportUrl` необязательны для всех статусов; опасные и некорректные URL отклоняются. Отсутствие `reportUrl` не блокирует переход личной встречи в `finished`.

У завершённых и текущей встреч порядок фиксирован. При перестановке меняется только `order` запланированных встреч: стабильные ID личных встреч и их пары сохраняются.

Нажатие на запланированную встречу выделяет её цветом. После нажатия ↑ или ↓ выделяется перемещённая встреча уже на новой позиции. Одновременно выделяется только одна строка; выделение хранится только в интерфейсе по стабильному ID и не изменяет JSON. Текст встречи доступен как обычная кнопка, поэтому выделение работает также с клавиатуры Enter/Space.

В режиме редактирования нельзя менять:

- ID командной встречи;
- формат 2×2, 3×3 или 4×4;
- формат личных встреч;
- ID спортсменов;
- ID и состав пар личных встреч;
- результат уже завершённой встречи.

Перед заполнением формы проверяется канонический порядок ID спортсменов `a1…aN` и `b1…bN`. Это исключает запись исправленных имён не тем спортсменам.

Отмена последнего завершения личной встречи в `v0.8.3` не реализована.

## Локальная интеграция с ttScore 0.3.5

Интеграция работает только в `mode=edit` и только когда `ttScore` и `ttscore_team` доступны под одним origin. Целевое размещение — `https://t39s.github.io/ttscore/` и `https://t39s.github.io/ttscore/team/...`.

`ttscore_team` читает существующие данные `ttScore 0.3.5` без изменения самого `ttScore`:

- `localStorage["ttScore:0.3.5:currentMeeting"]`;
- `localStorage["ttScore:0.3.5:livePublication"]`;
- `BroadcastChannel("ttScore:0.3.5:meeting")` как сигнал перечитать данные;
- `storage` event как резервный сигнал между вкладками.

В редакторе появляется блок `Данные из ttScore`. Имена спортсменов сопоставляются после удаления крайних пробелов, схлопывания внутренних пробелов и без учёта регистра. Поддерживаются прямое и обратное расположение A/B; при неоднозначности или несовпадении перенос блокируется.

Данные применяются только по явному действию пользователя:

- `Использовать live-ссылку` заполняет `liveUrl` текущей личной встречи;
- `Перенести результат` заполняет существующие `gamesA/gamesB`;
- JSON в этот момент не изменяется — дальнейшая подготовка выполняется штатными действиями редактора.

Финальный результат берётся из уже сформированных `ttScore` партий `games + pendingGame`; правила розыгрышей в `ttscore_team` не дублируются. Live URL строится из существующего `livePublication`, но `ttscore_team` не читает Firebase и не расшифровывает live-данные. `reportUrl` интеграция не создаёт.

Если данных `ttScore` нет, они несовместимы или браузер не даёт доступ к хранилищу, ручной workflow редактора остаётся полностью доступным. Polling не используется.

## Сохранение JSON на разных устройствах

В интерфейсе остаётся одна кнопка `Сохранить JSON`. Приложение само выбирает первый доступный механизм без определения модели устройства или браузера:

1. `showSaveFilePicker()` — диалог выбора имени и папки, если браузер его поддерживает.
2. `navigator.share({ files })` — системное меню, в котором на iPhone/iPad можно выбрать `Сохранить в Файлы`.
3. Blob-ссылка с атрибутом `download` — последний резервный вариант.

Все механизмы получают один и тот же объект `File`, точное имя `<id>.json` и точные байты подготовленного JSON. При отмене системного диалога следующий механизм не запускается. При технической ошибке приложение пробует следующий доступный механизм.

Папка заранее не настраивается: её выбирает пользователь в системном интерфейсе, если это допускает браузер и операционная система.

Для сохранения через Web Share вызов системного меню выполняется непосредственно внутри нажатия кнопки, без предварительного асинхронного запроса. Поэтому опубликованный источник проверяется перед созданием preview, а кнопка сохраняет именно проверенный и показанный JSON. Любое изменение формы или порядка встреч аннулирует preview и требует подготовить его заново. Источник теоретически может измениться уже после создания preview, поэтому проверка GitHub diff перед commit остаётся обязательной.

## Ручная публикация JSON и отчётов

1. Сохранить подготовленный `<id>.json`.
2. Открыть или создать в GitHub каталог `team/matches/<id>/`.
3. Загрузить в него `<id>.json`, заменив предыдущую редакцию при её наличии.
4. В этот же каталог загружать отчёты завершённых личных встреч. Для файлов рядом с JSON в `reportUrl` можно использовать относительную ссылку вида `./<report-file>`.
5. Проверить GitHub diff.
6. Создать commit.

Приложение не использует GitHub API, токены, авторизацию, Firebase или серверную часть.

## Модель JSON

Версия сохраняет `schemaVersion: 4`. Поле `individualMatchBestOf` принимает только `3`, `5` или `7`.

Редактор принимает только `schemaVersion: 4` и точное имя `<id>.json`. Для незавершённой командной встречи требуется ровно одна текущая личная встреча. Завершённую встречу можно открыть только для изменения ссылок. Автоматической миграции прежних схем нет.

Модель проверяет размеры команд, полное покрытие пар, порог побед, последовательность статусов, результаты личных встреч, дату, `updatedAt`, допустимые URL, целые JSON-числа и отсутствие неизвестных полей. `reportUrl` остаётся допустимым, но необязательным и для `finished`.

## Локальный запуск

Из каталога `ttscore_team_v0.8.3`:

```bash
python3 -m http.server 8000
```

Основные адреса:

```text
http://localhost:8000/team/ttscore_team_0.8.3.html?mode=create
http://localhost:8000/team/ttscore_team_0.8.3.html?match=<id>
http://localhost:8000/team/ttscore_team_0.8.3.html?match=<id>&mode=edit
http://localhost:8000/team/ttscore_team_0.8.3.html?mode=edit
```

Режим `file://` не поддерживается.

Перед принятием нужен ручной smoke `mode=edit` на целевом браузере, особенно iPhone/iPad Safari: раскрытие ссылок, перенос live/result из ttScore, единый preview, focus states и сохранение файла.

## Границы версии

Не реализованы автоматическое создание постоянного `reportUrl`, обмен между разными устройствами, запуск `ttScore` с предзаполненной парой, отмена завершения, изменение спортивного формата и состава пар начатой встречи, drag-and-drop, GitHub API, автоматическая публикация и серверная часть. Публикация не выполнялась; `ttScore_0.3.5.html` не изменялся.
