# ttScore Team v0.2.1

## Статус

- Назначение: статическое публичное оглавление одной командной встречи.
- Версия: `v0.2.1`.
- Статус: `IMPLEMENTED LOCALLY, NOT PUBLISHED, NOT YET ACCEPTED`.
- Данные примера: вымышленные.

`ttscore_team` не ведёт счёт личной встречи и не изменяет `ttScore 0.3.5`. Каждая личная встреча проводится отдельно в готовом `ttScore`, а командная страница хранит расписание, командный результат и ссылки.

## Публичный режим

```text
https://t39s.github.io/ttscore/team/ttscore_team_0.2.1.html?match=sever-yug-2026-09-05
```

Параметр `match` обязателен. Разрешены только строчные латинские буквы, цифры и дефисы. Публичная страница не содержит ссылки или кнопки перехода к редактору.

## Режим подготовки обновления

```text
https://t39s.github.io/ttscore/team/ttscore_team_0.2.1.html?match=sever-yug-2026-09-05&mode=edit
```

Редактор автоматически загружает опубликованный JSON выбранной встречи. Выбирать исходный файл на устройстве не требуется.

Для завершения текущей личной встречи:

1. Указать итог по партиям: `3:0`, `3:1`, `3:2` или зеркальный.
2. Вставить обязательную ссылку на отчёт завершённой встречи.
3. При наличии следующей встречи при желании вставить её live-ссылку.
4. Нажать **Подготовить обновление**.
5. Проверить новый командный счёт, следующую встречу или завершение командной встречи.
6. Нажать **Сохранить `<id>.json`**.

Подготовка выполняется целиком в браузере. Страница:

- переводит текущую встречу из `current` в `finished`;
- записывает результат и `reportUrl`;
- сохраняет прежний `liveUrl` завершённой встречи;
- пересчитывает командный счёт;
- при отсутствии пятой победы переводит первую `planned`-встречу в `current`;
- после пятой победы не запускает следующую встречу;
- обновляет `updatedAt`;
- повторно проверяет весь JSON перед разрешением скачивания.

Изменение любого поля формы аннулирует ранее подготовленный файл: нужно снова нажать **Подготовить обновление**.

## Ручная загрузка в GitHub

Редактор не хранит токен GitHub, не выполняет вход и не отправляет файл в репозиторий.

1. Открыть в GitHub каталог `team/team-matches/`.
2. Загрузить сохранённый JSON, заменив одноимённый файл встречи.
3. Имя должно в точности совпадать с `<id>.json`.
4. Если браузер сохранил файл как `<id> (1).json`, перед загрузкой переименовать его обратно в `<id>.json`.
5. Проверить diff и создать commit.

Защищённая ветка или ruleset репозитория могут потребовать отдельную ветку и pull request.

## Модель JSON

Версия использует прежний строгий контракт `schemaVersion: 2`. Командный счёт в JSON не хранится: он вычисляется из результатов `individualMatches`.

До пятой победы состояния идут в последовательности:

```text
finished* → current? → planned*
```

После пятой победы оставшиеся исходные позиции сохраняются как `planned`, а публичная страница отображает их как `Не требовалась`.

`reportUrl` может вести на автономный HTML-отчёт, защищённый отчёт `.ttscore` или открытый JSON. Разрешены относительные ссылки и HTTP(S); активные схемы и переходы `..` запрещены.

## Новая командная встреча

Для новой встречи достаточно добавить файл `team/team-matches/<id>.json`, записав тот же `<id>` в корневом поле `id`. HTML, JavaScript и CSS копировать или изменять не нужно.

## Локальный запуск

Из каталога `ttscore_team_v0.2.1`:

```bash
python3 -m http.server 8000
```

Публичный режим:

```text
http://localhost:8000/team/ttscore_team_0.2.1.html?match=sever-yug-2026-09-05
```

Редактор:

```text
http://localhost:8000/team/ttscore_team_0.2.1.html?match=sever-yug-2026-09-05&mode=edit
```

Режим `file://` не поддерживается, поскольку браузер блокирует загрузку соседнего JSON.

node --test tests/*.test.mjs

## Публичность и границы

Командные JSON-файлы, составы, результаты, live-ссылки и `reportUrl` публикуются открыто и сохраняются в истории Git. Защита от изменения обеспечивается правами записи в репозиторий.

Публикация не выполнялась. Firebase, Firebase Hosting, GitHub API и изменение `ttScore_0.3.5.html` этой версии не требуются.
