# ttScore Team v0.8.12 — чеклист судьи

## 1. Перед командной встречей

- [ ] Открыть `?match=<id>&mode=edit` и оставить editor открытым во время командной встречи.
- [ ] Войти учётной записью Firebase editor.
- [ ] Проверить Team date, составы, формат и planned-порядок.
- [ ] Запустить текущую пару в `ttScore`.
- [ ] Убедиться, что блок `Данные из ttScore` распознал именно текущую пару.

## 2. Live текущей встречи

- [ ] При необходимости включить Live в `ttScore`.
- [ ] Team автоматически синхронизирует Live-report и Live-scoreboard в Firebase.
- [ ] Отдельно готовить/publish JSON только ради Live в штатном случае не нужно.

Если Team сообщает, что automation ожидает Firebase login, выполнить вход. После восстановления сети синхронизация повторится автоматически.

## 3. Во время личной встречи

- [ ] Вводить счёт только в `ttScore`.
- [ ] Не переносить промежуточный счёт в Team.

## 4. После последнего очка

- [ ] Team автоматически сохранит финальный результат локально.
- [ ] **Не требуется** нажимать «Перенести результат», готовить transition JSON или публиковать Firebase вручную.
- [ ] Пока `ttScore` остаётся на той же завершённой встрече, Team не публикует finished автоматически — это окно Undo.

### Если нужен Undo

- [ ] Выполнить Undo в `ttScore` до выхода из этой встречи.
- [ ] Team должен удалить/обновить pending result автоматически.
- [ ] После повторного правильного финала продолжить обычный цикл.

## 5. Подтвердить завершение и перейти дальше

Есть два штатных варианта:

### Вариант A — «Новая встреча»

- [ ] В `ttScore` выйти из завершённой встречи через `Новая встреча`.
- [ ] Team подтвердит final по предыдущему состоянию и автоматически опубликует transition в Firebase.

### Вариант B — следующая точная пара уже запущена

- [ ] Запустить следующую по расписанию пару в `ttScore`.
- [ ] Team проверит новый `matchId` и имена обоих спортсменов.
- [ ] Только точное совпадение первой следующей `planned`-пары разрешит automatic transition.
- [ ] Если Live уже включён, его ссылки войдут в то же новое состояние автоматически.

## 6. Подготовка следующей встречи в ttScore — текущее ограничение

До разрешённого изменения `ttScore` дата, имена следующей пары и `bestOf` всё ещё вводятся в setup `ttScore` вручную.

- [ ] Смотреть следующую пару в Team.
- [ ] Ввести в `ttScore` правильных спортсменов и формат.
- [ ] Отдельно выбрать первый server, сторону слева и фору по фактическим условиям встречи.

Team не пытается записывать эти значения во внутренний `currentMeeting` `ttScore`.

## 7. Если Team показывает неправильную следующую пару

- [ ] Не выполнять ручной transition.
- [ ] Сверить `Следующая` в Team с парой `ttScore`.
- [ ] Неправильная пара не будет принята automation как новая current.

## 8. Если требуется ручная коррекция результата

- [ ] Изменить `Итог по партиям` вручную только при наличии достоверного основания.
- [ ] После ручного изменения automation останавливается для этой публикации.
- [ ] Нажать `Подготовить переход вручную`.
- [ ] Проверить preview.
- [ ] Опубликовать в Firebase вручную.

## 9. Если редактируются сведения, отчёты или planned-порядок

- [ ] Завершить эти ручные изменения и опубликовать их либо перезагрузить источник.
- [ ] Пока есть непубликованный draft/preview, automation намеренно не перезаписывает Firebase.

## 10. Firebase conflict

Если сообщение говорит, что данные Firebase изменились после загрузки:

- [ ] Не повторять старый preview.
- [ ] `Перезагрузить источник`.
- [ ] Проверить current/pending/следующую пару.
- [ ] Automation повторно оценит допустимое действие на свежем source revision.

## 11. Последняя личная встреча командного матча

- [ ] Провести её в `ttScore`.
- [ ] При необходимости сделать Undo до выхода.
- [ ] После подтверждённого выхода Team автоматически опубликует final team state.
- [ ] Проверить public view и итоговый командный счёт.

## 12. Постоянные отчёты и GitHub archive

`reportUrl` не блокирует finished. После завершения его можно добавить отдельно.

Для finished GitHub fallback v0.8.11:

- [ ] Проверить final state в Firebase/public view.
- [ ] Сохранить канонический `<id>.json`.
- [ ] Разместить `team/matches/<id>/<id>.json` вместе с постоянными отчётами.
- [ ] При позднем изменении `reportUrl` обновить Firebase final JSON и archive JSON.

## Короткий штатный цикл v0.8.12

```text
ввод счёта только в ttScore
→ final определяется автоматически
→ Undo при необходимости
→ Новая встреча / точная следующая пара
→ Team автоматически публикует finished + next current
→ Live синхронизируется автоматически
→ судья вручную заполняет пока только setup следующей встречи в ttScore
```
